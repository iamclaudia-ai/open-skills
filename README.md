# open-skills

A small collection of [Claude Code](https://docs.claude.com/en/docs/claude-code) skills that ships alongside
**Open Anima**, a reference copy of a personal AI agent platform built on Claude Code. Some skills drive Anima
directly (its `anima` CLI, the Today board, session handoffs); the rest are habits that work in plain Claude Code
too. Read them as worked examples as much as tools: each `SKILL.md` is the instructions an agent follows, written
down after the hard way.

## The skills

| Skill                                                         | What it does                                                                                                   | Needs Anima?               |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------- |
| [`keeping-notes`](keeping-notes/SKILL.md)                     | A running `tmp/<task>/NOTES.md` (plan, done, open, hard-won facts), written as you go and read first after a compaction | No                         |
| [`handing-off-sessions`](handing-off-sessions/SKILL.md)       | Continue long work in a fresh session instead of compacting: notes, `HANDOFF.md`, `anima session handoff`      | For the handoff call; falls back to giving you the file |
| [`running-review-sessions`](running-review-sessions/SKILL.md) | Work through the PRs waiting on your review, one session per PR or stack, drafting each review to `tmp/reviews/` | For the board and handoffs; the queue tool runs anywhere |
| [`running-today-sweeps`](running-today-sweeps/SKILL.md)       | The scheduled morning sweep and day refresh that rank the Today board and write its note, plus example scheduler tasks | Yes                        |
| [`self-reviewing-prs`](self-reviewing-prs/SKILL.md)           | The agent's own pass over a PR it prepared: comment sweep, mutation-tested tests, screenshots, self-review notes | No                         |
| [`using-gh-stack`](using-gh-stack/SKILL.md)                   | Stacked PRs with the `gh-stack` CLI (generated by the tool itself)                                             | No                         |

## The human stays in the loop

Every skill here follows one rule: **the agent prepares; the human decides what leaves the machine.** The agent
reads, edits, commits locally, runs tests and drafts text. Before anything becomes visible to other people or
permanent (a push, opening or updating a PR, an approval or merge, a review, a comment, a chat message, an email, a
deploy) it stops, shows exactly what it's about to do, and asks. A yes covers what was asked about, nothing more.

- Review skills **draft** reviews to files (`tmp/reviews/<number>.md`); you read them and post them, or tell the
  agent to post a specific one.
- The scheduled sweeps change only the Today board's picks and note. Replies, tickets and updates they'd suggest
  arrive as drafts in the session's final message.
- Inside Open Anima, a session asks you on the board (`anima today ask`), which shows the question under the item
  and notifies you if it sits unanswered.

This is a starting point, not a ceiling. Teams that work with an agent for a while usually loosen specific gates on
purpose, one kind of step at a time, once they've watched how the agent handles it. Do that deliberately: change
the gate in your config or your project's `CLAUDE.md`, write down why, and keep the riskiest steps (anything
posted under your name, merges to shared branches, deploys) gated longest. Open Anima's
`docs/HUMAN-IN-THE-LOOP.md` explains where its gates live, which ones code enforces, and how to make one hard with a
session profile that denies the commands.

## Install

A skill is a folder with a `SKILL.md`. Claude Code loads skills from `~/.claude/skills/<name>/` (every project)
and from `<project>/.claude/skills/<name>/` (one project). Clone this repo anywhere, then link the skills you want.

**By hand:**

```bash
git clone <this repo> ~/open-skills
ln -s ~/open-skills/keeping-notes ~/.claude/skills/keeping-notes
ln -s ~/open-skills/handing-off-sessions ~/.claude/skills/handing-off-sessions
# …one link per skill
```

**With Open Anima's skills extension** (`docs/extensions/skills.md` in Open Anima): set
`extensions.skills.config.repoPath` in `~/.anima/anima.json` to this repo's folder, restart the gateway, then:

```bash
anima skills link --skill running-review-sessions                              # into ~/.claude/skills
anima skills link --skill running-today-sweeps --project /abs/path/to/project  # into one project only
anima skills list_skills                                                       # check placements
```

New Claude Code sessions pick up linked skills.

## Requirements

- **`gh`**, logged in, for anything touching GitHub. `self-reviewing-prs`' screenshot uploader needs gh 2.99.0 or newer
  (the first release with `gh pr edit --attach`).
- **`jq`** for the review queue tool and the JSON one-liners.
- **Bun** for the TypeScript scripts in `running-today-sweeps`; **Python 3** for `pr-screenshots.py`.
- **Open Anima's `anima` CLI on `PATH`** for the Anima-specific parts (`handing-off-sessions`' handoff call, the
  review queue's board questions and handoffs, `running-today-sweeps`). Open Anima's `docs/GETTING-STARTED.md`
  shows how.
- **`check-review-queue`**, bundled with Open Anima at `extensions/today/tools/check-review-queue`, for
  `running-review-sessions`. It's a standalone bash script (`gh` + `jq`), usable without the rest of Anima.
- **`gh-stack`** (optional): `npm install -g gh-stack` or `bun install -g gh-stack`.

## About `using-gh-stack`

`using-gh-stack/SKILL.md` is generated by the `gh-stack` CLI from the text compiled into the binary, so it matches
the installed version. To regenerate it after upgrading:

```bash
gh-stack learn > using-gh-stack/SKILL.md     # prints the skill to stdout
```

(or `gh-stack learn --skill --global --harness claude` to install it straight into `~/.claude/skills`). One hand
edit to redo after regenerating: the branch names in the "From scratch" example use a placeholder prefix (`you/`).
Note that its "Agent/CI mode" section is about running without prompts: `--yes` also accepts pushes, so an agent
that must wait for a human's go before publishing should add `--no-push` (or `GH_STACK_NO_PUSH=1`) and push only
after the go.

## Working on these skills

- `running-today-sweeps/scripts` has tests: `cd running-today-sweeps/scripts && bun test`.
- Keep skills generic: no names, hosts, accounts or company details. They're meant to be read and copied.
